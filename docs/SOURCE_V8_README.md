# Dragon Dawwa

A responsive community website in English, Tamil and Sinhala. A Vinext/Cloudflare Worker serves the site and its Quran Foundation backend. Editable pages and assets live in `public/`; `dist/` is generated by the Sites build.

Features: source-linked editorial readings, search and category filters, browser-local bookmarks and writing, notebook export, a quiet reflection space, community information, and planned learning-circle details.

Editorial status: initial content references Qur'an 17:36 and 16:125, Egypt's Dar Al-Ifta, and Jonathan Brown's research on hadith criticism. No scholar endorsement or review is claimed. Tamil and Sinhala readings are editorial renderings, not presented as verbatim Qur'an translations. Community invitations, scholar names, dates, and live recordings must be supplied before those features can be activated.

Data: notes, questions, language preference, and bookmarks stay in localStorage. No form sends information. Google Fonts is used with system-font fallbacks. All artwork is local. Garden artwork is an imagined architectural scene generated with the built-in image-generation tool for this site.

Checks: JavaScript syntax; local file references, unique IDs, anchor links, translation completeness; script-level checks of search, filtering, bookmarking, language changes, dialog content and local writing. Browser rendering QA was unavailable in this environment.

Image brief: a peaceful ivory pointed arch framing a green garden at dawn, warm sun, brass lanterns, refined geometric details, editorial architectural photography, no figures or lettering.

## Public research hub (4 October 2026)

`public/research.html` adds a complete English/Tamil/Sinhala research page with a public-record profile, a searchable 108-entry Anuradhapura mosque directory, official governance resources, proposed activities, a voluntary participation plan, and an evidence-gap register.

The census explorer uses DCS 2024 religion tables A3 (25 districts), A7 (340 DS divisions) and GN religion data (14,003 GN divisions, loaded by district). Anuradhapura has 960,080 residents, including 83,979 Muslims; nationally the counts are 21,781,800 and 2,337,379. These count persons by religion, not ethnicity, households or mosque members. GN religion values under 10 are grouped into Other by DCS; source dashes are preserved as null and displayed as not separately reported. Higher-level religion totals come directly from A3/A7, never a sum of the privacy-protected GN column.

District, DS and GN total-population checks reconcile. Explicit DS spelling variants are matched across the two DCS tables and checked against total population. No mosque-to-GN association or service-area boundary is inferred. Mosque records retain source spelling and registration strings, with only whitespace normalised. Blank city fields remain blank.

Reproducibility: `scripts/extract-public-data.py` reads the four downloaded government files and rebuilds `public/data/`; `data/provenance.json` records their URLs, SHA-256 hashes and extraction rules. Run `node scripts/check-research.mjs` to validate translations, census reconciliation, suppression, filters, pagination, CSV export, mosque lookup and language persistence. Checks use a small DOM stub and do not verify browser layout. Browser rendering QA remains unavailable in this managed environment.

Data is public aggregate/institutional data. No named residents, personal religious profiles, mosque membership registers or private contact lists are included. CSV exports contain the current filtered aggregate results, census year, geography, suppression note and source URL. Only the existing language preference is saved to localStorage. Proposed programmes have no invented schedules or speaker endorsements. Current trustee appointments, founding date, specific activities, land records, accounts and jamaat boundaries remain unverified in the sources reviewed.


## Quran Foundation connection (4 October 2026)

`/quran` and `/quran.html` provide the live API reader; both existing HTML pages and `/research` are preserved. The supplied credentials authenticate successfully against **prelive**, whose current catalogue exposes Al-Fatihah and Al-Baqarah, an English translation among other language resources, and two reciters. Production permission is not claimed. Tamil and Sinhala interface text is available; these Quran translation resources are absent from the current test catalogue, explicitly stated in the reader. No machine translation of canonical source text is performed.

`QURAN_CLIENT_ID`, `QURAN_CLIENT_SECRET` (both Sites secrets), and `QURAN_ENVIRONMENT=prelive` are configured in hosted runtime settings, never checked into source. Tokens use the official client-credentials flow and remain server-side. Only two read endpoints are exposed: `/api/quran/bootstrap` and `/api/quran/verses`, with validated resource IDs, fixed upstream hosts, request timeouts, token reuse, one retry after 401, and bounded short-lived content caching. Errors do not echo upstream credentials or responses. Production switch requires approved production credentials and a new deployment using `QURAN_ENVIRONMENT=production`.

Verse Arabic is rendered as supplied. Named translations use a formatting-only DOM allowlist; source links provide full footnotes/context. Audio uses provider CDN URLs with no autoplay or preload; only one recitation plays at once. Browser-local saved places use `dd-quran-place`; no Quran.com user scopes, account linking, paid API, subscriptions, or AI-generated commentary are enabled. Static artwork, existing research data, and the mosque directory order are preserved.

Build with `node /root/.codex/plugins/cache/openai-curated-remote/sites/1.0.0-a/scripts/build-site.mjs`. Run `node scripts/check-research.mjs` and `node --test scripts/check-quran.mjs` for data and backend checks. A live provider smoke test is separate from mock tests. Browser rendering QA is unavailable in this managed environment.

above continue to describe the original home notebook and questions only.
